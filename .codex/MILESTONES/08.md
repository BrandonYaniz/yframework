# Milestone 8: Workflows and Scheduling

## Governing contract

Workflows are durable sequential prepare, commit, and cleanup coordination built on jobs. Components own transitional data. Production data changes only in the final commit phase, after prepare succeeds. Record-level rejection is result data, not job execution failure. Workflow commit must verify both current job lease ownership and workflow concurrency ownership in the same transaction as production mutation. Workflow advancement and next-step creation are idempotent and restart-safe. Schedules support once, five-field cron, and anchored interval. Missed policies are coalesce and replay, default coalesce. Overlap policies are allow, skip, and queue_one, default queue_one. queue_one permits one active plus at most one pending logical run. scheduled_for is durable. Cron uses OS local time, skips nonexistent spring-forward occurrences, and treats repeated fall-back wall time as one logical occurrence.
