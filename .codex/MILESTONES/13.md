# Milestone 13: Lifecycle, CLI, and Health Hardening

## Governing contract

Canonical startup order is bootstrap stderr logger, static config validation, full logger, application/component composition, static registry registration/freeze, startup MariaDB connection, DB compatibility check, migration lock, migrations, runtime-state load/validation, foreground/background pool creation, runtime service construction, control-plane startup, Unix-socket bind/readiness, then normal request acceptance. Static validation completes before DB mutation. Liveness, readiness, and degraded capability are distinct; MariaDB is readiness-critical, required integrations may make the app unready, optional integrations degrade capability, and disabled capabilities are not failures. Applications own main and executable. Standard commands are serve, install, migrate, validate, with version recommended; validate is nonmutating and serve never daemonizes. Shutdown is QUIESCE, DRAIN, CLOSE DATABASE, TERMINATE. Quiesce stops every new-work source and disables readiness. Drain preserves active correctness work, leases, and heartbeats within bounded deadlines. Database closes only after correctness-sensitive work can no longer start or finish. Socket cleanup is ownership-safe, full logging remains available through most shutdown, and bootstrap stderr is the final fallback.
