# Milestone 4: Identity and Authorization

## Governing contract

Human/browser authentication is passkey-only in v1. Multiple passkeys are allowed, and the final usable passkey cannot be removed or disabled. Sessions and bearer tokens use high-entropy opaque secrets with only verifier/hash material persisted. Roles group permissions, but authorization checks permissions, not role names. Direct user grants union with role grants. Application, installation, and user capabilities narrow by intersection where combined. Security-sensitive authorization caches use revision-based invalidation, not TTL alone. Resource authorization remains typed and component-owned. Stable public identities use UUIDs, not internal numeric keys. Security-relevant changes produce append-only framework security events without secrets.
