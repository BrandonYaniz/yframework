# Milestone 15: Release Hardening

## Governing contract

No new subsystem features. Prove release readiness through full unit, race, fuzz, real-MariaDB, migration, lifecycle, crash-recovery, retention, load, security, compatibility, documentation, and reproducibility validation. Critical hot queries must have reviewed indexed EXPLAIN plans and recorded performance baselines, without inventing arbitrary universal throughput promises. Test realistic backlogs, provider outages, memory/goroutine/file-descriptor growth, and bounded retention cleanup. Perform targeted authentication, authorization, CSRF/origin, UDS, SSRF, template/directive, secret-leak, LLM trust-boundary, admin-permission, and dependency-vulnerability review. Validate zero-to-current and previous-supported-schema upgrades, stable names, config compatibility, public-consumer compatibility, and data preservation. Complete user, administrator, developer, configuration, schema, CLI, recovery, and .codex documentation. Release requires no unresolved release-blocking security or architectural issue and a reproducible clean-clone build/test path.

## Completion rule

A task is complete only when its behavior matches the governing sources, relevant tests pass, exported API changes are documented, secrets are redacted, ownership boundaries remain intact, and no architecture-affecting decision was silently invented.
