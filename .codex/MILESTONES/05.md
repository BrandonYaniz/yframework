# Milestone 5: Actions, Routes, Server, and Rendering

## Governing contract

Actions have concrete typed Go inputs and outputs and remain presentation-neutral. Dynamic routes are application-owned MariaDB configuration referencing stable registered actions/renderers/permissions. Route grammar permits literals and {name} parameters only, rejects structurally ambiguous parameter shapes, gives literal segments precedence, and produces 405 after path matching. Input mappings are declarative and cannot execute SQL, scripts, or arbitrary transforms. Trusted user/application/installation identity comes only from framework context. HTTP is served over an application-configured Unix socket with safe stale-socket handling, explicit proxy trust, bounded request limits, cookie security, and browser cross-origin protection. Runtime route state is validated into immutable atomic snapshots before activation.
