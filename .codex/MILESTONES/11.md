# Milestone 11: LLM and yllmd

## Governing contract

Components use purpose-based framework LLM APIs and never open the yllmd socket or encode its protocol. Application configuration maps stable LLM purposes to yllmd groups/profiles. yFramework owns one durable authoritative request record per logical operation, separate request/response content, attempt history, cancellation, correlation, and a dedicated outbound LLM FIFO separate from the ordinary job lane and yllmd's own inference queue. States distinguish queued, submitted, accepted, running, completed, failed, canceled, and quarantined. Request content is durable before submission, terminal response is durable before caller wake, stable request identity survives retries, and uncertain submission remains explicitly uncertain. Crash-associated retries default to quarantine after three qualifying attempts. Streaming is not resumable across framework-process interruption in v1. Prompt/output content is excluded from ordinary logs, output remains untrusted, and default content retention is 90 days with review/quarantine holds. Throughput estimates use a rolling default of 15 qualifying completed requests per concrete model and expose confidence rather than false precision.
