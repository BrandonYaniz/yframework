# Milestone 10: Messaging and Notifications

## Governing contract

Notification intent is distinct from messaging delivery. Components register stable message purposes and never receive SMTP clients or credentials. Outbound messages are durable before delivery, with compact current state, separate content, and separate attempt history. V1 uses remote SMTP. Messaging owns delivery retry semantics, provider retry budgets, circuit breakers, rate limits, and ambiguous-delivery handling while actual eligible attempts run through the single ordinary background lane. Notification contacts are separate from subscriptions. Anonymous destinations require verification, verification tokens are hash-only, unverified contacts default to 30-day retention, and verification proves control only for the registered purpose, not unrelated consent. Completion notifications are created only after the underlying durable domain fact commits.
